How the Platform Works

A three-step cashless boarding experience that works even without internet connectivity.

💳

1. Top-Up Transport Credit

Students load transport credits via EcoCash, InnBucks, ZimSwitch, or bank transfer. Funds are held in a non-custodial licensed escrow account.

📱

2. Generate QR Boarding Pass

The Student App generates a short-lived HMAC-SHA256 signed opaque token that expires every 60 seconds. No internet required to show the QR code.

📷

3. Conductor Scans & Validates

The Conductor App scans the student's QR. Online: instant server debit. Offline: cryptographically bounded provisional queue, synced when back online.

🏦

4. Automated Operator Settlement

Every validated journey creates an immutable double-entry ledger record. Operators receive transparent, automated daily settlement reports.

ARCHITECTURE
Technical Architecture

Non-Custodial Ledger

Double-entry journal entries in minor currency units (USD cents / ZWG ngwe). No direct custody of student funds.

HMAC-SHA256 Credentials

Short-lived opaque QR tokens with 60-second TTL, signed using HMAC-SHA256. Anti-replay protection via server-side jti tracking.

Offline Resilience

Bounded offline queue (max 10 items per session) with cryptographic provisional acceptance. Reconciled automatically on reconnect.

RBAC Session Auth

Role-based access control (STUDENT / CONDUCTOR / OPERATOR / ADMIN) with bearer token session management.

RBZ Sandbox Ready

Architecture designed for Reserve Bank of Zimbabwe Fintech Regulatory Sandbox entry under NPS Act [Chapter 24:23].

Monorepo Structure

pnpm workspace with shared TypeScript contracts and domain packages. Android apps in Gradle multi-module setup.
